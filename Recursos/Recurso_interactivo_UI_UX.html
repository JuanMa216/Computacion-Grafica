Diseñar para ver, comprender y actuar

Una interfaz no se evalúa solo por su apariencia. Explora cómo las decisiones gráficas orientan la atención, comunican el estado del sistema y hacen posible —o difícil— completar una tarea.

Dos lentes, una experiencia

UI Lo que se presenta y se manipula: composición, tipografía, color, controles y movimiento.
+
UX La experiencia completa: utilidad, comprensión, esfuerzo, emociones y contexto de uso.

La UI forma parte de la UX, pero la UX también depende del contenido, el flujo, el rendimiento y el servicio.

Idea guía: una pantalla atractiva puede producir una mala experiencia, y una interfaz visualmente sobria puede funcionar muy bien. Diseñar exige observar a las personas, definir la tarea y comprobar el resultado.

02 · Distingue

UI y UX no son sinónimos

Se complementan, pero responden preguntas diferentes. Confundirlas suele producir soluciones bonitas para problemas mal definidos.

Interfaz de usuario · UI

¿Cómo se presenta la interacción?

Trabaja con la capa visible y manipulable del sistema. En Computación Gráfica incluye decisiones de representación y respuesta visual.

  • Composición, retícula, tipografía y color.
  • Botones, campos, iconos, estados y animaciones.
  • Activos vectoriales o raster y adaptación a pantallas.
Experiencia de usuario · UX

¿Qué vive la persona al lograr su objetivo?

Considera el recorrido completo antes, durante y después de usar la interfaz, en un contexto real y con restricciones concretas.

  • Utilidad, facilidad de aprendizaje y confianza.
  • Arquitectura de información, contenido y flujo.
  • Investigación, prototipado, medición e iteración.
UX = interfaz + contenido + comportamiento + rendimiento + contexto + servicio

03 · Aplica

Principios que se pueden observar y probar

Filtra las tarjetas por enfoque. Cada una incluye una pregunta útil para revisar un boceto, prototipo o producto.

Visual

Jerarquía

Tamaño, peso, posición y espacio establecen un orden de lectura. Si todo grita, nada guía.

Prueba: ¿qué se percibe primero, segundo y tercero?

Visual · Accesibilidad

Contraste

El contraste de luminancia mejora la legibilidad; el color no debe ser la única señal de significado.

Prueba: ¿se entiende en escala de grises y con brillo bajo?

Visual

Proximidad

Los elementos cercanos se interpretan como relacionados. El espacio también comunica estructura.

Prueba: ¿los controles y datos relacionados forman grupos claros?

Interacción

Consistencia

Patrones repetibles reducen el aprendizaje y permiten transferir expectativas entre pantallas.

Prueba: ¿la misma acción conserva nombre, aspecto y ubicación?

Interacción · Accesibilidad

Retroalimentación

El sistema debe comunicar qué ocurrió, qué está ocurriendo y qué puede hacerse después.

Prueba: ¿cada acción importante produce una respuesta perceptible?

Interacción

Prevención y recuperación

Las restricciones y confirmaciones evitan fallos; deshacer y mensajes claros facilitan recuperarse.

Prueba: ¿la interfaz ayuda sin culpar a la persona?

Accesibilidad

Operación diversa

Las funciones deben poder usarse con teclado, puntero, tacto y tecnologías de asistencia.

Prueba: ¿el foco es visible y el orden de navegación tiene sentido?

Evaluación

Contexto de uso

Las necesidades cambian según las personas, las metas, el dispositivo y el entorno físico o social.

Prueba: ¿para quién, para qué y en qué condiciones se diseña?

Evaluación

Evidencia

El gusto del equipo no sustituye la observación: mide éxito, tiempo, errores y percepción.

Prueba: ¿qué dato permitiría decidir entre dos alternativas?

04 · Itera

Un proceso centrado en las personas

No es una secuencia rígida. Los hallazgos de una prueba pueden devolver el proyecto a cualquier etapa.

01

Comprender

Identificar personas, objetivos, dispositivos, entorno y restricciones.

02

Definir

Convertir hallazgos en requisitos y criterios observables de éxito.

03

Organizar

Estructurar contenido, navegación, flujo de tareas y jerarquía.

04

Prototipar

Representar ideas con la fidelidad mínima necesaria para aprender.

05

Evaluar

Observar tareas, medir resultados, interpretar y volver a diseñar.

05 · Conecta

¿Dónde entra la Computación Gráfica?

UI/UX define qué experiencia se necesita; la Computación Gráfica aporta medios para representarla con claridad, fluidez y eficiencia.

Decisión técnica → consecuencia perceptiva

Raster y vectorLa elección afecta nitidez, escalabilidad, peso y adaptación de iconos e imágenes.
Color y luminanciaEspacios de color, calibración y contraste condicionan lo que realmente se percibe.
Retículas y transformacionesPosición, escala y alineación construyen jerarquía y permiten responder a distintos tamaños.
AnimaciónEl movimiento puede explicar continuidad y estado; también puede distraer o causar malestar.
RenderizadoLatencia, estabilidad y tasa de cuadros influyen en control, confianza y comodidad.
Interfaces 3DProfundidad, oclusión, perspectiva y selección espacial añaden oportunidades y carga cognitiva.

Mini reto de observación

  1. Elige una aplicación que uses con frecuencia.
  2. Define una tarea concreta, por ejemplo: “exportar una imagen”.
  3. Registra cuántos pasos exige y dónde dudas.
  4. Señala una decisión visual y una decisión de flujo que influyan en el resultado.
  5. Propón un cambio y explica qué evidencia confirmaría que funciona.

Evita: “lo cambiaría porque se ve mejor”. Prefiere: “lo cambiaría para que la acción principal se encuentre antes; lo comprobaría midiendo tiempo y errores”.

06 · Revisa

Lista breve antes de entregar

✓La pantalla responde a una tarea y a un contexto definidos.
✓La acción principal se distingue sin competir con todas las demás.
✓Etiquetas, agrupación y navegación reducen la necesidad de recordar.
✓Los estados de espera, éxito y error tienen retroalimentación clara.
✓Texto y controles conservan contraste, foco y tamaño operable.
✓El prototipo fue observado con tareas y criterios de éxito.
